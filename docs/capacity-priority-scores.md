# 商城内存与 SSD：容量优先综合评分

2026-11-04 用户要求采用聊天「内存性能评分方法」最后给出的两套公式。适用范围是商城内存与 SSD 的商品评分：卡片、搜索结果、详情和后台标签均显示同一综合分；详情另外显示只比较速率/时序或读写的性能子分。CPU/GPU 仍用 `performance-v1`，其他类别仍显示规格标签。本次不修改 F04 推荐门槛、用途权重或候选排序。

## `capacity-priority-v1`

综合分 `S = 100 × (r + 0.9P) / (K − 1 + 0.9)`。`r` 是容量在本类别固定表中的下标（从 0 开始），`K` 是表的长度，`P` 是 0–1 的性能子分。较小一档的分子至多 `r + 0.9`，相邻大容量档的分子至少 `r + 1`，故性能不能使小容量反超大容量。档位不随上架、下架、库存或售价变化。

| 类别 | 按规范 GB 排序的固定档位 |
| --- | --- |
| 内存 | 8、16、24、32、48、64、96、128 |
| SSD | 128、240、250、256、480、500、512、960、1000、1024、1920、2000、2048、4000、8000 |

内存采用套装总容量，SSD 按十进制 GB 归一化，保留并校验原始容量与单位（1 TB = 1000 GB）。不同容量（如 SSD 的 500 GB 与 512 GB）不合并。表外容量、未定义参考速率的 DDR 代际不评分，待明确支持范围时以新规则版本扩档。

- 内存：`T = (2000/R) × (0.5CL + 0.3tRCD + 0.2tRP)`，`B = min(1, R/Rref)`，`L = clamp((18 − T)/9, 0, 1)`，`P = 0.6B + 0.4L`。`R` 单位为 MT/s；DDR4、DDR5 的 `Rref` 分别为 3600、6400。`T` 是计算指标，非实测系统延迟。后台维护标称速率及同档位 CL/tRCD/tRP（周期），另记时序对应速率以拒绝不同速率的档位混用。不能把 EXPO/XMP 标称档位理解成整机一定能达到的速率。
- SSD：`P = 0.55 × min(1, 顺序读/7000) + 0.45 × min(1, 顺序写/6000)`，速度单位 MB/s。7000 和 6000 是本版本的评分封顶参考值，适用于当前样本范围。高于上限的部分不再加分；未计随机读写、缓存耗尽后的持续写入等指标。

后端用 BigDecimal 计算，最后以 HALF_UP 保留 6 位小数。商城和后台显示的综合分和性能子分四舍五入到小数点后一位。公开详情 `performance.score` 仍是综合分（十进制字符串），`performance.performanceScore` 是 `100P`（有有效内存/SSD 评分时返回）；`mappingVersion` 为 `capacity-priority-v1`，`reference.inputs` 含参与评分的参数及各自来源。关键参数或来源缺失、档位错配或原始容量无法换算时，返回空综合分和原因，页面显示“待核验”。后台通过普通商品参数表单维护；新评分字段可以留空并上架，填入非空数值时仍须按已有商品规则提供来源。更改品牌或型号时，先清空旧的速率和时序（内存）或顺序读写速度（SSD）；保存时也移除这些字段的旧来源和备注，之后按新型号补录。
