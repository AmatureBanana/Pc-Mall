# 配置组入车契约

任务14复用现有购物车、V20 配置组表和 V22 数量字段，提供合法配置整组入车、去重、库存聚合及整组删除。配置组引用商城真实销售 SKU，没有独立整机 SKU 或整机库存。

2026-11-11 用户确认保留现有 DIY 内存数量能力：每类一个销售 SKU，内存可选 1～4 根，其他类别各 1 件。数量计入兼容检测、去重、库存需求和金额；组内不能拆改。当前 F03 沿用九项核心规则及显卡明确选择约定，见[兼容契约](compatibility.md)。

## 接口与归属

所有接口要求 Session 登录；写操作要求 CSRF。账户归属取自服务端认证主体，不接受 `user_id`、`accountId` 等客户端身份字段。成功和购物车业务错误响应均为 `Cache-Control: no-store`。

| 接口 | 行为 |
| --- | --- |
| `POST /api/cart/configurations` | 复验并整组加入本人购物车，相同配置返回已有组 |
| `GET /api/cart` | 返回单品 `items` 和独立的 `configurations`，金额按当前售价计算 |
| `DELETE /api/cart/configurations/{id}` | 只删除本人整组及其明细，保留其他组和单品 |

八类独显配置请求示例：

```json
{"selections":[{"category":"CPU","productId":1},{"category":"MOTHERBOARD","productId":3},{"category":"GPU","productId":5},{"category":"MEMORY","productId":14},{"category":"SSD","productId":9},{"category":"PSU","productId":11},{"category":"CASE","productId":12},{"category":"COOLER","productId":8}],"memoryQuantity":2}
```

示例 ID 仅说明结构，实际使用商品查询返回的当前真实引用。七类核显配置省略 GPU，并提交等于 CPU 商品 ID 的 `integratedGraphicsCpuId`。服务端重新核实核显能力和完整性，不能只凭该字段获得通过。

`memoryQuantity` 默认 1。每个 `selections` 明细只允许 `category`、`productId`。重复 JSON 字段、重复类别、类别不符、额外数量、客户端价格/名称/来源/参数/通过标识均拒绝。不能提交部分配置替换已有组，也没有组内数量或删除接口；普通单品接口只操作单品表。

## 复验、去重与事务

1. 在本人购物车行锁内串行处理写入，再按商品 ID 升序取得所有引用商品的共享行锁。
2. 商品锁取得后才建立一致读取快照，复核真实类别、当前可售状态和库存，读取当前价格，复用 F03 重新检查完整性及全部适用核心规则。
3. 配置身份由规范类别顺序、商品引用和数量决定，数据库以 `(cart_id, signature)` 唯一约束兜底。输入顺序、商品名称、来源及价格都不能产生相同配置的第二组。
4. 重复配置仍重新验证当前数据，但新增需求为零，成功时不增加购物车修订。不同数量的内存代表不同配置。
5. 新组头、全部明细和购物车修订在同一事务提交；包括第八条明细写入失败在内的任何失败均整体回滚。失败后可重试，不留下半组。

后台修改价格、状态、库存或参数时先锁同一商品行，因此入车等待已在进行的商品写入完成，再验证其提交后的数据。共享锁只保持本次事务的一致性；入车不会预占库存、扣减库存或锁定后续价格。

同 SKU 可同时属于普通单品和多个不同配置组，归属分别保留。加购或改量时汇总本人全车该 SKU 需求，超过当前可售量即拒绝并保留原车。普通单品的 99 件限制只作用于单行，跨项总需求可以超过 99。读取也按聚合需求标注库存不足。

`configurations` 每组包含 `id`、`items`、当前金额字符串 `amount` 和可售状态 `valid`；每条明细包含真实 SKU、类别、数量、现价、小计及库存状态。`valid` 仅表示当前可售库存状态，读取时的完整兼容诊断和结算由任务15继续实现。`total` 包含全部当前金额；`validTotal` 仅计入有效单品和完整有效组。浏览器拒绝缺少必要类别或数量非法的组响应，不将残缺明细当成入车成功。

## 页面与失败反馈

DIY 的“转入购物车”先展示当前配件和参考金额。游客先登录并恢复原配置，登录后需要再次主动确认；登录、恢复和取消均不触发自动加购。提交使用当前选择，不发送旧检测结果或客户端金额。

购物车分别展示单品和整组明细，包括类别、名称、销售 SKU、固定数量和现价。组内不能独立勾选、改量或移除；整组删除不会吞并或删除同 SKU 的单品及其他组。重复提交不会多建组，现价变化在后续读取中更新。

若连接断开或响应异常，页面保留确认栏并提示“方案入车结果暂未确认”，用户可重试或打开购物车核对；不自动重复提交，也不把传输失败描述为确定回滚。相同配置的服务端去重让用户重试保持一组。明确的业务拒绝则保留服务端原因。

| 拒绝情形 | HTTP / 错误码 |
| --- | --- |
| 游客或失效会话 | 401 / `UNAUTHENTICATED` |
| 缺少或无效 CSRF | 403 / `CSRF_INVALID` |
| 格式、类别、引用或伪造字段无效 | 400 / `INVALID_CART_INPUT` |
| 配置不完整、不兼容或参数未知 | 409 / `CONFIGURATION_NOT_COMPATIBLE` |
| 当前不可售或全车聚合缺货 | 409 / `CART_STOCK_LIMIT` |
| 删除不存在或他人配置组 | 404 / `CART_ITEM_NOT_FOUND` |
| 明细写入失败或数据库不可用 | 503 / `CART_UNAVAILABLE` |

不实现任务15的整组替换、报价确认、混合预结算，或后续订单与库存预占。没有新增迁移、依赖、外部代码或数据。验证结果见[任务14证据](evidence/task-14.md)。
