# DIY 当前标签页工作区

任务09提供 `/#diy` 三栏选配工作区，复用商城商品与详情。游客和登录账户都可进入；每类最多选一个 SKU。内存按单根销售，同一型号可选多根，数量受主板已核验的内存插槽、可售库存和四根上限约束。未选定主板时可先选一根；更换主板后保留原数量，若超限须调低才能入车。其他类别各选一件。

## 商品与选配

- 八类候选来自现有 `GET /api/products?category=...&keyword=...`，不另建数据副本，不包含下架商品。品牌和价格排序作用于当前查询结果；缺货仍展示但不能新选入。
- 任意类别均可先选，同类再选替换原引用；移除一个类别不影响其他类别。清空须在确认框中确认，取消不修改配置；确认后重置候选筛选和当前类别。
- `/#diy/product/{id}` 复用商城详情显示型号、销售SKU、库存、完整参数、单位、来源及单根内存容量，关闭回到工作区。

## 服务端参考报价

公开只读接口：`GET /api/diy/quote?revision=2&CPU=1&MEMORY=7`。GET 不持久化工作区，不改变库存，响应 `Cache-Control: no-store`。无需登录或 CSRF 写令牌；其他请求和现有写接口仍遵守原权限与CSRF策略。

参数接受一个 `revision`、八类中每类最多一个正整数商品 ID，以及可选的 `memoryQuantity`（1～4，默认 1；大于 1 时须选内存）。重复参数、非法 ID、缺失修订或额外字段返回 400/`INVALID_CONFIGURATION`。服务端按当前单价和根数报价，兼容检测另行核验插槽。

`data` 包含：

| 字段 | 含义 |
| --- | --- |
| `revision` | 原样返回本次配置修订，用于客户端匹配当前编辑 |
| `items` | 每个所选引用的类别、productId、quantity（内存根数，其他为 1）、state、message、当前product及amount |
| `total` | 所有选择都有效时的完整参考总价；存在问题时显式为null；空配置为`"0.00"` |
| `validSubtotal` | 只对当前有效商品按销售单位合计；有问题时不冒充完整配置报价 |
| `compatibility` | 固定`NOT_CHECKED`，本票不执行或宣称通过兼容检测 |

`state` 为`VALID`、`NOT_FOUND`、`CATEGORY_MISMATCH`、`OFF_SALE`或`OUT_OF_STOCK`。不存在商品的product为null，失效商品amount为null；引用仍保留以供替换或移除。

服务在一个只读事务快照内读取同一商品表的当前状态、售价和可售库存，BigDecimal精确求和并以两位小数金额字符串返回。全部选择不必齐全即可报价，金额不是下单锁价或兼容准入结果。数据库故障沿用503/`CATALOG_UNAVAILABLE`，不能转换成空配置或零元成功。

## 临时状态与异步保护

`sessionStorage`键为`pc-mall.diy.workspace.v1`，仅保存：

```json
{"version":1,"revision":2,"selections":[{"category":"CPU","productId":1,"source":"DIY"},{"category":"MEMORY","productId":7,"source":"DIY"}]}
```

选择多根内存时另存 `memoryQuantity`。每次实际选择、同类替换、调整内存根数、移除和确认清空增加修订。重复点击当前商品和取消清空不改变修订。刷新报价不改变选择修订。刷新页面、再次进入工作区和窗口重新聚焦均读取当前服务端报价。

恢复校验版本、修订、商品引用与来源、内存根数，不信任本地价格、库存或检测结论。恢复后重新读取当前商品；浏览器本身可能复制标签页的初始sessionStorage，此后各标签页独立，不做跨标签页同步或永久多方案。

## 游客登录恢复（2026-11-08）

游客在 `/#diy` 点击统一登录（或注册后转登录）时，登录框记住来源是工作区。登录成功后回到同一 `/#diy`，保留原商品引用、`source` 和修订，重新读取当前商品、价格、库存与参数，并调用当前完整 F03 检测；不自动加购或下单，不建立购物车组、预占、审计或永久游客账户。恢复成功后右侧候选商品也会重新读取，避免左侧仍显示登录前的列表。登录失败、密码错误或关闭登录框都留在原工作区，配置与修订不变。

恢复只复用现有两个公开只读入口——`GET /api/diy/quote` 与 `POST /api/compatibility/check`——不新增后端接口或数据表。恢复结果以工作区顶部“登录恢复”段落说明：

- 恢复了几项引用与当前修订，并声明数据来自服务端当前值、本次恢复不产生购买副作用。
- 失效引用（`NOT_FOUND`、`CATEGORY_MISMATCH`、`OFF_SALE`、`OUT_OF_STOCK`）逐项列出原因，引用仍留在工作区，可继续替换或移除；即使没有可比快照也会报告。
- 可比快照中原先缺货、下架等失效引用恢复为可售时，逐项说明此前状态与当前可售状态；即使参数指纹和价格均未变化，也不声称登录前后数据一致。不记录或比较正库存的具体数量。
- 变价以「电源参考价由 ¥100.00 变为 ¥130.00」这类逐项差异说明。参数或上下架变化以一条工作区级提示表达：「服务端参数指纹与登录前所见不同」。指纹（`catalogVersion`）由规则版本、商品引用、上下架状态与参数生成，**不含价格**；但商品 revision 在调价和库存调整时同样递增，因此无法从 revision 反推是价格还是参数变化，故不逐项归因到某个商品。
- 无法比较时（无快照、损坏、修订不匹配或规则版本已变）只如实声明已按服务端当前数据重验，不声称“与登录前一致”。
- 恢复期间用户继续编辑时，页面立即把旧恢复标记为“恢复期间配置已变更”，旧请求的报价与检测结果不覆盖新修订；所有响应仍须匹配当前修订、请求身份和规则版本。重复触发恢复只由最新一次尝试发布结果，旧尝试不会产生错误提示。

管理员在工作区登录时仍按既有认证契约进入管理后台（不进入恢复流程）；`登录失败、取消或关闭登录框`均不改变工作区，且只在打开登录框时冻结一次“登录前所见”。

### 诊断快照

登录框打开时工作区仍在后台持续重检，会覆盖诊断快照，因此打开登录框时把快照**冻结**一份（`seenBaseline`）；明确区分“尚未冻结”和“已冻结但无快照”，后者始终无法比较，不使用登录期间才生成的快照补位。恢复失败后的重试保留同一份冻结基线，成功、放弃或配置修订变化后才释放。恢复中的报价与检测已执行当前权威读取，聚焦、重新可见和定时重检不会取消它们；继续编辑仍立即发起新修订请求并使旧恢复失效。

`pc-mall.diy.sign-in.v1` 是当前标签页的短期登录上下文，仅含版本1、固定来源 `diy` 与冻结诊断快照（或明确的 `null`）。它使 `#login`/`#register` 刷新后仍能返回原工作区；初始化只在这两个登录路由读取，快照采用下述相同校验。注册转登录保留上下文，成功、取消或通过历史导航离开认证流程均删除；其他路由初始化时也清理残留。不保存密码、会话令牌或权威结果，不跨标签页同步，存储失败不阻断当前页面的内存流程。

登录请求在途时仍可关闭登录框。关闭后已由服务端建立的会话无法撤回，响应到达后更新账户显示，但旧请求不改变用户当前导航；若用户仍在原 DIY 工作区，则重新读取当前服务端数据并显示恢复摘要，保留原冻结诊断基线。

`sessionStorage` 键 `pc-mall.diy.seen.v1` 只保存用户上次成功看到的内容，用于恢复时解释差异：

```json
{"version":1,"revision":8,"ruleVersion":"f03-core-graphics-choice-v3","catalogVersion":"<64位SHA-256>","items":[{"category":"PSU","productId":11,"state":"VALID","amount":"100.00"}]}
```

写入时机是报价与检测同时成功且修订一致；写入失败不影响编辑或恢复。读取时校验版本、修订、非空规则版本文本、指纹为 64 位小写十六进制、至多八项、互异类别、正整数 ID、金额格式与状态，与工作区存储同等严格；无效快照按“无法比较”处理，不在挂载时删除。只有配置修订、规则版本及全部类别与商品引用均匹配时才比较并允许声明一致。

该快照**仅供诊断**：不参与金额计算、不用于判断可售或库存、不构成兼容或准入依据，也不作为跳过重验的凭证。金额、库存与兼容结论始终来自恢复时重新请求的服务端响应。

变更时先保存引用，再发报价请求。报价请求8秒超时，可取消；每个响应须匹配当前请求及配置修订，候选查询也使用现有取消/过期保护策略。新请求立即失效旧金额。请求失败保留编辑引用并展示重试，不显示旧成功报价。存储读取、格式或写入失败均明确提示；格式损坏的原存储不会在挂载时删除，用户主动编辑后才保存新的配置，写入失败仍可继续当前内存中的编辑。

## CPU 核显候选（2026-11-08）

DIY 类别显示为「显卡」。选中具有已核验核显的 CPU 后，显卡候选首位固定显示「核显（使用 CPU 自带）」；品牌筛选、搜索与价格排序作用于独显商品，核显作为当前 CPU 的附属选项保持置顶。规格在卡片内展开，展示 CPU 参数的 igpu 字段及逐项来源。没有核显、未选 CPU、CPU 不可售或详情不可核实时，不展示可选核显；参数失败可重试。

核显不创建商品、销售 SKU 或独显引用，不出现在商品浏览中。选择核显会移除 GPU 商品引用，额外价格 ¥0.00，核显候选由当前 CPU 已核验能力提供；当前不再执行图形输出检测，显卡一栏仍为必选项。选择独显、替换/移除 CPU、移除显卡或清空都会清理相应核显选择。功耗包含于 CPU 峰值估算，不额外叠加或将未知峰值改成零。

临时状态增加可选的 `integratedGraphicsCpuId`，仅用于保存用户显式选择的核显；必须对应已选 CPU，且不能与 GPU 商品并存。这个字段不传给报价接口；传给兼容接口后由服务端重新核验 CPU 核显能力，不包含客户端规格或通过结论。刷新会重读 CPU 当前规格；详情暂不可用时保留「核显 · 参数待重验」引用，仍可移除。旧版仅含商品引用的工作区仍可恢复。

核显规格与来源见[核显参数记录](integrated-graphics.md)。渲染参考没有可比的已核验数据，显示待核验，不借用 CPU 或独显跑分。


## 配置修订建议精简与显卡检测调整（2026-11-08）

按用户圈图删除主板建议后的「再核对内存代际与实际条数」、逐条缺件列表和核心通过范围提示。保留冲突原因/解决建议、未知参数、总体状态、重检和检测记录。按用户最终澄清，显卡一栏必须明确选择核显或独立显卡，未选择的方案不能通过；不能仅因为 CPU 有核显就自动认为已选择核显。取消的是 C07 有效图形输出路径判断，不再核验主板或显卡视频输出路径。核显必须绑定当前具有已核验核显能力的 CPU，无核显 CPU 只能选独显。该选择由前端记录并由后端校验。已选独显的安装接口、空间、功耗及失效引用检查保持有效，检测契约更新为九项 `f03-core-graphics-choice-v3`。核显仍是 DIY 免费候选，不是独立商品。


## 自动检测（2026-11-08）

配置修订建议移除「配置或参数变化后需重检」与「重新检测」按钮。添加、替换、移除、清空硬件以及切换核显/独显时，工作区统一变更入口立即刷新报价和兼容检测，使用当前全部硬件引用检测冲突；请求开始清除旧结果，取消/请求身份及修订校验阻止旧响应覆盖。无需用户手动触发。保留检测失败时的重试入口，以及聚焦、重新可见和可见时每30秒的参数重验。
