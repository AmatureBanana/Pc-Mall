# DIY 当前标签页工作区

任务09提供 `/#diy` 三栏选配工作区，复用商城商品与详情。游客和登录账户都可进入；每类最多一个销售 SKU、一个销售单位，内存双条套装仍只计一个销售单位。没有预设配置、永久游客账户、整机 SKU 或库存预占。

## 商品与选配

- 八类候选来自现有 `GET /api/products?category=...&keyword=...`，不另建数据副本，不包含下架商品。品牌和价格排序作用于当前查询结果；缺货仍展示但不能新选入。
- 任意类别均可先选，同类再选替换原引用；移除一个类别不影响其他类别。清空须在确认框中确认，取消不修改配置；确认后重置候选筛选和当前类别。
- `/#diy/product/{id}` 复用商城详情显示型号、销售SKU、库存、完整参数、单位、来源及内存套装实际条数，关闭回到工作区。

## 服务端参考报价

公开只读接口：`GET /api/diy/quote?revision=2&CPU=1&MEMORY=7`。GET 不持久化工作区，不改变库存，响应 `Cache-Control: no-store`。无需登录或 CSRF 写令牌；其他请求和现有写接口仍遵守原权限与CSRF策略。

参数仅接受一个 `revision` 和八类中每类最多一个正整数商品ID，均限于JavaScript安全整数范围。重复类别、非法ID、缺失修订、额外价格/数量/所属用户字段均为400/`INVALID_CONFIGURATION`。客户端不能指定商品金额或数量。

`data` 包含：

| 字段 | 含义 |
| --- | --- |
| `revision` | 原样返回本次配置修订，用于客户端匹配当前编辑 |
| `items` | 每个所选引用的类别、productId、固定quantity=1、state、message、当前product及amount |
| `total` | 所有选择都有效时的完整参考总价；存在问题时显式为null；空配置为`"0.00"` |
| `validSubtotal` | 只对当前有效商品按销售单位合计；有问题时不冒充完整配置报价 |
| `compatibility` | 固定`NOT_CHECKED`，本票不执行或宣称通过兼容检测 |

`state` 为`VALID`、`NOT_FOUND`、`CATEGORY_MISMATCH`、`OFF_SALE`或`OUT_OF_STOCK`。不存在商品的product为null，失效商品amount为null；引用仍保留以供替换或移除。

服务在一个只读事务快照内读取同一商品表的当前状态、售价和可售库存，BigDecimal精确求和并以两位小数金额字符串返回。全部选择不必齐全即可报价，金额不是下单锁价或兼容准入结果。数据库故障沿用503/`CATALOG_UNAVAILABLE`，不能转换成空配置或零元成功。

## 临时状态与异步保护

`sessionStorage`键为`pc-mall.diy.workspace.v1`，仅保存：

```json
{"version":1,"revision":2,"selections":[{"category":"CPU","productId":1,"source":"DIY"},{"category":"MEMORY","productId":7,"source":"DIY"}]}
```

每次实际选择、同类替换、移除和确认清空增加修订。重复点击当前商品和取消清空不改变修订。刷新报价不改变选择修订。刷新页面、再次进入工作区和窗口重新聚焦均读取当前服务端报价；本票不实现任务12的登录自动恢复与重验交接。

恢复仅接受版本、合法修订和至多八个互异类别的商品引用与来源，不信任本地价格、库存或检测结论。恢复后重新读取当前商品；浏览器本身可能复制标签页的初始sessionStorage，此后各标签页独立，不做跨标签页同步或永久多方案。

变更时先保存引用，再发报价请求。报价请求8秒超时，可取消；每个响应须匹配当前请求及配置修订，候选查询也使用现有取消/过期保护策略。新请求立即失效旧金额。请求失败保留编辑引用并展示重试，不显示旧成功报价。存储读取、格式或写入失败均明确提示；格式损坏的原存储不会在挂载时删除，用户主动编辑后才保存新的配置，写入失败仍可继续当前内存中的编辑。

## 参考图 UI 调整（2026-11-07）

按用户新参考图调整为三栏：左侧显示八类硬件及已选商品名称，支持查看详情、替换与移除；中间为品牌筛选、类别内搜索和候选商品卡片；右侧为参考总价、兼容性检查、配置修订建议及底部操作。类别显示顺序为 CPU、独立散热器、主板、内存、独显、SSD、电源、机箱，商品引用和每类一个销售单位的约束保持一致。

“重置配置”沿用二次确认清空；“保存方案”显式重试保存当前标签页的商品引用与修订，成功显示保存反馈，保存失败保留可编辑内容并明确报错。保存使用现有 sessionStorage，不建立永久方案库或新增后端持久化。

兼容性区域按用户后续要求精简：移除常驻 C01～C05 列表与底部展开入口，兼容性检查仅以红色小点列出冲突名称。具体原因与相应解决方案按冲突分别放入配置修订建议，冲突消除后两处内容同时隐藏。配置未齐、参数未知和检测失败仍通过总体状态如实显示；修订建议取自当前选择、商品状态及分项诊断，不照搬参考图中的示例硬件建议或“当前配置兼容”结论。图形输出、功率和空间等尚未完成的检查在配置修订建议中明确提示待核验。

界面与验证见[参考图 UI 调整记录](evidence/diy-ui.md)。
