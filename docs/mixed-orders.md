# 配置组混合下单与 SKU 聚合

任务17扩展任务16的 `SingleItemOrders`、报价和库存事务。没有新增订单状态机或整机库存；支付、取消、超时和订单列表仍由后续任务实现。

## 请求与最终准入

`POST /api/orders` 沿用原字段，允许 `itemIds` 与 `configurationIds` 任意非空组合。例如：

```json
{"revision":3,"itemIds":[11],"configurationIds":[21,22],"quoteToken":"预结算确认的64位指纹","requestKey":"order-mixed-unique"}
```

身份来自 Session，服务端读取本人购物车中的整条单品与完整组。客户端不能传组内配件、数量、来源、旧兼容结论或金额；额外字段、重复JSON字段、重复ID及非法ID仍拒绝。组不能作为普通购物项拆分购买，不存在或他人组返回404。请求还须通过 CSRF、购物车修订、报价和幂等检查。

取得所有选中商品的升序写锁后，逐组重新读取当前配件、参数及F03全部适用P0结果。必须满足七类基础硬件、明确可用核显或独显、类别唯一、内存1～4根且其余类别各1件。缺件、未知、不兼容、下架或缺货返回409 `CART_SELECTION_INVALID`。报价或商品信息变化返回409 `PRICE_CONFIRMATION_REQUIRED`，用户须重新核对并确认；确认不是锁价。未选失效项不参与准入或清理。

## 聚合、快照与事务

同SKU的库存需求来自选中单品和每个选中组的实际数量。单品行仍限1～99件，但库存聚合没有99件上限；99件单品加两套各需1件的配置，按101件预占。库存不足时整个选中订单失败。

复用购物车锁 → 幂等记录 → 预占头 → 商品ID升序写锁的顺序和 `READ_COMMITTED`。配置成员由同一购物车锁保护；后台写参数、价格和库存遵守商品行锁。最终校验、订单头、组快照、明细、库存预占、选中单品/整组删除、购物车修订和幂等记录在一个事务中提交或回滚。

V24新增 `order_configuration`，保存订单中的原配置组ID和成交小计，不引用已删除的购物车组。`order_item.configuration_id` 保存明细归属，通过组合外键关联订单组快照；单品为null。SKU、名称、型号、类别、单价、数量、小计及归属均保存成交值。组不会因后续参数、商品信息或价格修改而改变。

订单结果沿用 `items` 扁平明细，新增 `configurations: [{id, amount}]`。同SKU可以出现在单品及不同组中，各明细单独保留；`configurationId` 关联分组。金额为CNY两位小数字符串。`GET /api/orders/{number}` 仅查询本人历史快照；单品订单的 `configurations` 为空数组。

幂等指纹绑定用户、操作、修订、选中单品、报价以及排序后的组ID；保留既有纯单品指纹格式。成功后原内容原键重放先返回原单，不重验已删除的组或再次预占；换组选项不能复用同键。失败不保留成功记录。

## 浏览器

购物车按整组选择，报价确认后可创建混合订单。结果页分别显示成交单品和各配置组的明细及小计，页面刷新仍读历史快照。客户端拒绝缺少分组、关联不完整或成员结构不完整的响应，保留原请求重试上下文，不把部分数据展示为成功。

服务端拒绝及传输结果未知时的恢复沿用[单品订单契约](single-item-orders.md)：使用原内容原键核对同一笔订单；确定的业务冲突允许重新报价。重试上下文仅在当前页面运行期保留。数据库故障验证与浏览器响应故障分别记录，后者不冒充数据库回滚证据。
