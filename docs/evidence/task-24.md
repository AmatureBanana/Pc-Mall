## 复现方法与库边界

将 `JAVA_HOME` 指向本机的 JDK 21 安装目录，再从仓库根目录运行。工作负载使用原有 `test` 配置连接 MySQL 的 `pc_mall_test` 库及专用账户，应用和负载驱动在本机随机端口通信。演示库和常规回归目录独立。专项测试在启动后事务式加载数据，以本轮唯一前缀创建商品和账号，完成后清理本轮数据。专项与常规回归串行运行，避免两个任务同时改动测试库或干扰统计。

```powershell
$env:MAVEN_USER_HOME = "$PWD\.local\maven-user"
./scripts/local-db.ps1 start
. ./.local/env.ps1
python scripts/verify-performance-acceptance-data.py
./mvnw.cmd '-Dtest=PerformanceAcceptanceIT' test
./scripts/test.ps1
```

评分核验可追加 `--snapshot <冻结 ZIP 路径>` 验证 ZIP 指纹、归档样本与选样顺序。专项原始输出位于 `target/performance-acceptance/`，包含运行环境、逐请求状态、纳秒耗时和聚合 P95。详细 JUnit 结果在 `target/surefire-reports/`。

## 负载口径

每项以屏障同步发送 3 波预热和 10 波正式请求。会话建立、CSRF 初始化、填车、创建报价与用户支付等待均在计时区间外。耗时从 Java HTTP 客户端开始发送到读完响应体，包含应用与 MySQL 往返。P95 使用正式样本按耗时排序后第 `ceil(0.95 × n)` 个值。预热、正式请求和正确性竞争分列。正式请求均断言业务成功，竞争请求按场景断言成功或业务冲突。

- F03 以一套有效独显配置发起完整检测，10 个独立访客会话。
- F04 办公、游戏、创作分别以 20,000 元预算和 10 并发验证，每次核对完整兼容结果、商品、分数和总价的稳定性。
- F05 20 个独立登录用户。每车在 29～30 条单品明细之间执行加入、读取、改量、移除。
- F06 20 个独立登录用户分别下单，使用不同 SKU，避免把故意制造的旧报价冲突混入正常下单样本。订单列表和详情在每账户已建 13 单时计时。有限库存、重复支付、释放及后台并发另行测试。
- F07 管理员分页查询商品和订单，使用同一管理员会话发出 20 个请求。订单查询时已创建 260 单。2 秒为初步目标。

本轮环境为 Windows 11 家庭版 26H2（26300.9974）、AMD Ryzen 7 8845H（8 核 16 线程）、16,419,446,784 字节可见物理内存、JDK 21.0.10、Spring Boot 3.5.16、Tomcat 10.1.55、MySQL 8.0.45、Hikari 连接池上限 5、InnoDB 缓冲池 128 MiB。应用、MySQL 和客户端运行在同一台机器上。**设备条件与 F03 四核 8GB 级基线不同**，报告记录本机实测，各性能目标在指定硬件上的结果仍待验证。
