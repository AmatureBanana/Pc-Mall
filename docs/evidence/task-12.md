## 已交付

游客在 `/#diy` 打开统一登录（含注册后转登录）时，登录框记住来源工作区；登录成功后回到同一工作区，保留原商品引用、`source` 与修订，重新请求当前商品、价格、库存与参数，并调用现有完整 F03 检测。不自动加购、下单或创建购物车组。

- 恢复结果以“登录恢复”区域说明：恢复项数与修订、数据来源为服务端当前值、本次恢复无购买副作用；正常时显示“当前数据与登录前所见一致”，无法比较时不作此声明。
- 失效引用逐项诊断（`NOT_FOUND`/`CATEGORY_MISMATCH`/`OFF_SALE`/`OUT_OF_STOCK`）并保留引用以便替换或移除；变价显示前后金额差异；全局 `catalogVersion` 指纹变化提示工作区参数或上下架变化，不从商品 revision 反推变更类别。
- 恢复期间继续编辑时旧恢复标记为“恢复期间配置已变更”；旧响应受既有请求身份、修订与规则版本校验保护，不覆盖新修订。
- 登录失败、错误密码或关闭登录框都留在原工作区，配置与修订不变。

没有新增后端接口、数据库迁移或依赖：恢复复用 `GET /api/diy/quote` 与 `POST /api/compatibility/check`。新增**仅用于诊断**的 sessionStorage 快照 `pc-mall.diy.seen.v1`（用户主动确认允许），不参与金额、可售、库存或准入判断，也不作为跳过重验的凭证。独立复审后另增加短生命周期 `pc-mall.diy.sign-in.v1`，仅存当前标签页登录来源与冻结诊断快照（含明确的无快照 `null`）；用于认证页刷新后的返回目标，不存密码、令牌或权威结果。注册转登录保留，成功、取消或历史导航离开认证流程即清理，存储失败不阻断当前页内存流程。详见[当前契约](../diy-workspace.md)。

## 两轴审查与修复

按 implement 要求使用 code-review 技能，两个全新上下文代理并行只读审查 Standards 与 Spec；代理未修改文件或运行测试，自动化验证由主代理执行。审查覆盖全部实现、测试、接口文档与新增文件，排除原有 `.idea/jsLibraryMappings.xml`。

**Standards（初轮 3 项，均已修复）**

1. 文档 `docs/diy-workspace.md` 的失效引用枚举漏了 `CATEGORY_MISMATCH`，而实现与 `QuoteItem` 都包含它 → 补齐枚举，并补浏览器断言（无快照时失效引用仍诊断）。
2. 文档声称 `readSeen` 校验“指纹格式”，实际只判 `typeof === 'string'` → 改为与 `loadCompatibility` 相同的 `/^[a-f0-9]{64}$/`。
3. 三处重复的 `${label}：${message}` 构造与多余字段（`RestoredChange.label`、`RestorationState.ready` 携带未被读取的 `quote`/`check`）→ 合并为单一 `note()`、删除未用字段，`ready` 只保留 `restored` 计数。

**Spec（初轮 4 项真实缺陷 + 3 项边界，均已修复/说明）**

1. **假阳性**：调价与库存调整都会 `revision=revision+1`，原实现把“商品 revision 变了但价格没变”判为参数变化，产生误报 → 改为只按不含价格的 `catalogVersion` 指纹做工作区级提示，不逐项归因（指纹不含价格，但 revision 无法区分价格/参数，故不声称逐项）。测试断言同步修正，未保留假阳性断言。
2. **基线被覆盖**：`#login` 不改变 `diyOpen`，工作区持续 30 秒/聚焦重检会覆盖“登录前所见”快照，导致变价在恢复时被抹去 → 打开登录框时冻结 `seenBaseline`（内存，不新增存储），恢复优先使用；新增“登录框打开期间变价”回归，断言仍能报告 ¥100.00 → ¥130.00。首轮该回归失败，暴露出登录成功路径提前清空基线，已一并修正。
3. **恢复竞态**：两次重叠 `restore()` 会互相中止请求，旧尝试可能发布假错误 → 引入 `restoreAttempt` 序号，仅最新尝试可发布结果，并要求报价与检测的修订都等于当前修订。
4. **登录来源泄漏**：取消登录后 `signInOrigin` 未复位，后续经 `#login`（后退/前进、改密跳转）会被误带入恢复 → `closeAuth()` 与登录成功路径均复位来源与基线。
5. **管理员路径**：草稿把管理员也带入 `#diy`，违反既有 story 74“统一登录后进入后台” → 恢复原有契约，管理员仍进后台；新增回归确认管理员登录后进入后台、且工作区引用仍在。
6. **候选列表未刷新**：恢复只重读报价与检测 → 恢复成功时一并重读候选商品。
7. **购物车断言**：`tables(db)` 相等性断言在无购物车入口时按构造恒真 → 证据中如实标注该条为“无持久化副作用”证据，并明确“购物车组创建”要到任务13才有真实表面可验证，不宣称已验证。

**豁免的审查意见**：审查建议删除 `RestoredChange.kind`/`category`/`productId` 字段——保留，因为它们是恢复摘要的结构化定位信息，UI 目前只读 `message`，但删除会把“哪一类、哪个商品变化了”这一语义挤进字符串，属于有意保留的最小结构。

最终 Standards 遗留 0 项、Spec 遗留 0 项；两轴最高严重度均为已修复的真实缺陷。
